### Контрольный вопрос

**Что разрешает политика AdministratorAccess? Почему для повседневной работы нельзя использовать root?**

Политика `AdministratorAccess` даёт пользователю полный доступ ко всем сервисам и ресурсам AWS в аккаунте. Root-пользователь имеет ещё больше прав, и его права нельзя ограничить. Если его пароль утечёт, злоумышленник получит полный контроль над аккаунтом и деньгами на нём. Поэтому root используют только для редких задач, а в обычной работе применяют пользователя IAM.

### Контрольный вопрос

**Что такое User data и когда выполняется этот скрипт? Выполнится ли он повторно после перезагрузки экземпляра?**

User data — это скрипт, который передаётся экземпляру при создании и выполняется автоматически при самом первом запуске, от имени root. С его помощью сервер настраивается без ручной работы. После обычной перезагрузки скрипт повторно не выполняется.

### Контрольные вопросы

**Какая из проверок укажет на проблему, которую можете исправить вы, а какая на проблему на стороне AWS?**

Instance status check проверяет саму виртуальную машину: загрузилась ли система и отвечает ли она. Такая проблема на нашей стороне, её можно исправить (например, перезагрузить экземпляр или поправить настройки в системе). System status check проверяет оборудование и сеть AWS, поэтому проблема там на стороне AWS. Attached EBS status check показывает, доступны ли подключённые диски.

**В каких случаях стоит включать детальный мониторинг?**

Детальный мониторинг присылает метрики раз в минуту вместо раз в пять минут, но стоит дополнительных денег. Его стоит включать, когда нужно быстро замечать скачки нагрузки: например, на важных рабочих серверах, при автоматическом масштабировании или когда ищут причину кратковременных сбоев. Для учебного сервера хватает базового мониторинга.

## 6. Задание 4. Подключение по SSH

Файл ключа `Codjebas-keypair.pem` был скачан в папку `Downloads`. Работа выполнялась в Windows. При первой попытке SSH отказался использовать ключ с ошибкой `Permissions ... are too open`, так как к файлу имели доступ другие пользователи. Права были исправлены командами `icacls`: отключено наследование прав и оставлено право на чтение только для текущего пользователя.

```
icacls "%USERPROFILE%\Downloads\Codjebas-keypair.pem" /inheritance:r
icacls "%USERPROFILE%\Downloads\Codjebas-keypair.pem" /grant:r "%USERNAME%:R"
```

Подключение к экземпляру выполнено командой:

```bash
ssh -i "%USERPROFILE%\Downloads\Codjebas-keypair.pem" ec2-user@3.125.3.200
```

При первом подключении было подтверждено добавление сервера в список известных (`yes`). После входа приглашение терминала стало `[ec2-user@ip-172-31-xx-xx ~]$`. Состояние nginx проверено командой:

```bash
systemctl status nginx
```

Служба nginx находится в состоянии `active (running)`.

### Контрольный вопрос

**Почему для входа на экземпляр EC2 используется ключ, а не пароль?**

Пароль можно угадать или подобрать перебором, а подобрать SSH-ключ практически невозможно. Приватный ключ хранится только у владельца и по сети не передаётся, на сервере лежит только открытая часть. Поэтому вход по ключу намного безопаснее.

## 7. Задание 5. Статический сайт

На компьютере были созданы три страницы, ссылающиеся друг на друга: `index.html` (главная), `about.html` («О нас») и `contact.html` («Контакты»).

Файлы скопированы на сервер командой `scp`, выполненной на локальном компьютере:

```bash
scp -i "%USERPROFILE%\Downloads\Codjebas-keypair.pem" index.html about.html contact.html ec2-user@3.125.3.200:~
```

Затем на сервере по SSH файлы были перенесены в папку, из которой nginx отдаёт страницы:

```bash
sudo cp ~/*.html /usr/share/nginx/html/
ls -l /usr/share/nginx/html
```

Напрямую через `scp` положить файлы в `/usr/share/nginx/html` нельзя, так как эта папка принадлежит root, а подключение выполняется под `ec2-user`. Поэтому сначала файлы копируются в домашнюю папку, а затем переносятся через `sudo`.

После этого сайт открылся в браузере по адресу `http://3.125.3.200/index.html`, ссылки между страницами работают.

### Контрольный вопрос

**Что делает команда scp и чем она похожа на ssh?**

`scp` копирует файлы между компьютером и сервером. Работает она поверх SSH: использует тот же порт 22, тот же ключ и того же пользователя `ec2-user`. Разница в том, что `ssh` открывает терминал на сервере, а `scp` только передаёт файлы.

### Контрольный вопрос

**Чем Stop отличается от Terminate? За что вы продолжаете платить, пока экземпляр остановлен?**

`Stop` просто выключает экземпляр: его можно снова запустить, а диск EBS и данные на нём сохраняются. `Terminate` удаляет экземпляр навсегда, и обычно вместе с ним удаляется и корневой диск. Пока экземпляр остановлен, за вычислительные ресурсы платить не нужно, но продолжают оплачиваться диски EBS (и, например, снимки или Elastic IP, если они есть).
